# 短剧解说混剪 Skill

把一部短剧二次创作成 **N 条(默认 4)不同高光故事线的纯解说混剪**。和 `short-drama-editor`(保原声精剪)的区别:本 skill **画面全静音**、用 **AI 重写的第三人称解说稿**配 TTS 配音、**逐句快切**,并做 **去硬字幕** 降同质化。

## ⛔ 平台分轨(执行第 0 步,必读,严禁串台)
视频号和抖音**只共用前半段管线**(ASR→去字幕→TTS→tag),**后半段要求完全不同,执行时必须严格分开、不能掺在一起**。

**第 0 步:先锁定这部剧归属哪个平台**(视频号的剧只做视频号,抖音的剧只做抖音——**默认一部剧只做一个平台**,不擅自给视频号剧做抖音版、也不反过来)。锁定后,**下面只读目标平台那一列,跨列的时长/脚本/版式/命名一律不用**。

| 维度 | 📺 视频号 | 📱 抖音 |
|---|---|---|
| 推流机制 | 停留≥72秒 + 互动率≥8% + 社交裂变 | 完播率%(35%)+ 前3秒留存(40%) |
| 时长 | **90–120s 甜点**(≤180,**不准砍短**,短了过不了72秒门槛) | **45–75s 短版**(越短完播越高) |
| 开头 | 前3秒炸 + 留存做平 + 可保留铺陈/评述 | **前15秒重构**(高潮前置/前3句零铺垫/10-15s二钩) |
| build 脚本 | `build_narration_mixcut.py`(arg5=GLOBAL_SPEED) | `build_narration_mixcut_douyin.py`(arg5=is_ai, arg6=GLOBAL_SPEED) |
| 解说字幕 | 逐句短字幕,压原字幕位 | 逐句短字幕,压原字幕位 |
| CTA / 版式 | 横排 CTA 底部 + 声明顶部 + 剧名底部 | **竖排 CTA 贴左缘** + AI标注/真人标注在顶部 |
| 声明 | 固定 AI 声明(无分支) | **is_ai 分支**(AI剧顶部AI标注 / 真人剧右上竖排"剧情演绎") |
| 互动/引导 | 金句自然勾赞·**悬念断点**·「点左下角看全集」(挂短剧小程序组件,需粉>1000) | 追更关注钩 + 完播导向 |
| 标题 | **≤16字硬规** | 无字数限,前15字成钩 |
| 文件/草稿命名 | `slN.json` → `剧名_SLN_角度名` | `slN_dy.json` → `剧名_角度名_抖音短版` |
| 合规 | 严禁诱导赞转关注评论/煽动对立/导流站外/绝对化用语 | 平台推荐规则 |

> **铁律**:① 执行任何一步前先确认当前在哪条轨;② 同一次执行只用目标平台那一列的参数/脚本/命名,**绝不混用**(如:给视频号剧用抖音的45-75s时长、或用 douyin build 的竖排CTA = 错);③ 若一部剧确实要两平台都发,也必须**当成两次完全独立的执行**,各自锁平台、各写各的稿(`slN.json` vs `slN_dy.json`)、各跑各的 build,中间不串参数。

## ⛔⛔ 星图/分销推广合规闸(抖音侧·写稿前必过·违反=限制自见/限流)
**血泪实测(2026-06-22):** 用本 skill 给《蛊镯新月》出的 **271s 全剧完整弧解说(引用 EP1-32)一发布即被抖音判「涉及不当形式宣发短剧」→「限制自己可见」(直接废)**。平台原文=**"禁止使用未授权的新发剧集内容来推广短剧"**。改成 **EP1-19 内单故事线短版**才过审。

**先回答:这条解说是不是"星图/分销推广任务"的投稿?**(账号在 creator.douyin.com 变现中心接了某剧的推广任务、靠播放/付费分佣结算)。**是 → 下面 6 条死规矩,缺一条就限:**
1. **按授权集数上限剪(最硬)**:任务页有「当前可使用素材:1-X集」,**只能用前 X 集、绝不超**(超出平台明文"对视频/合集/账号进行处罚")。X 是**按时间滚动**的动态值,**每次发稿前现查**:creator.douyin.com → 变现中心 → 我的任务 → 点剧卡 → 看「可使用素材」+「查看其他时间可剪辑集数」。(蛊镯实测当前=1-19集;脚本 `d:\抖音内容\scripts\duanju_task_detail.py` 能抓但 SPA 导航飘,需多试)。
2. **单故事线,绝不做"全剧完整弧"**:一条只讲一个角度,**讲完整部剧=替代观看全集=损害原作者收益=违规**。连红尘短剧爆款也是每条只讲一个故事线。
3. **不剧透关键反转/结局**:断在钩子/狠话峰值,把答案留在全集里。
4. **≤3min**(2026-06-05 抖音新规真人短剧单集硬上限 3min,建议 90s;也天然满足"别讲太全")。
5. **不盗原片/不搬运洗稿**:必须有原创解说观点(已是本 skill 强项)。
6. **导流走官方挂载组件**(左下角系统锚点),CTA 烧字幕只是强化;**别导流站外/私域**。

**违规后别申诉**(申诉通道只对"持完整短剧完整版权"者开,推广方申诉必驳)。

> **⚠️ 这条闸 supersede 下面 Step1/Gate① 的"抖音2026做长5-8min主推"**——那套"做长拉停留"**只适用于自有账号 organic 解说**,**一旦是星图/分销推广任务,以本闸为准(≤3min + 集数上限 + 不剧透 + 单线)**。两者别混。

## 输入
- 短剧视频文件夹(多集 mp4/mkv,按文件名自然排序),例 `D:\短剧\演绎剧本\母亲的沉默\母亲的沉默-全集`
- 已有 `{剧名}_精剪\asr_work\merged_data.json`(没有则先跑 ASR+merge,可借用 short-drama-editor 的 asr_transcribe.py / merge_transcripts.py)

## 输出
- N 个剪映草稿(默认 4),每条一个高光故事线,**90s–3 分钟(≤180s)**
- 中间产物在 `{剧名}_精剪\asr_work\narration\`
- **每条一组「带钩子标题 + 标签」**(发布文案),写到 `asr_work\narration\titles.md`(见 Step 6)

## 产物形态(硬约定)
- **画面全静音**,跟解说逐句快切,镜头间叠化 200ms
- 竖屏 1080×1920
- **画面变速 1.15**(source 取 dur×1.15,显示时长仍=解说,不改时间轴、不动音轨)——**降同质化的关键层,保留不动**
- **解说语速(TTS)=1.2**:节奏靠 narration json 的 `speed_ratio=1.2` 合成,**不是**后期变速,所以音调/音色完全自然(豆包按目标语速正常合成,无拉伸痕迹)。这与上面的「画面变速 1.15」是**两个独立参数**:画面变速管降同质化、TTS 语速管解说节奏,各调各的
- **画面放大 107%**(scale 1.07,轻微裁边/构图)
- 解说音量 **1.4(飙黄不飙红:响而不爆)**;BGM **0.30** 铺底(响而不压解说)
- **每条故事线配不同的 BGM**(同剧 N 条不能用同一首;BGM 时长须 ≥ 该条片长,否则结尾静音)
- **同一故事线内不能连着出现相同画面**:相邻两 shot 的源时间窗不得重叠、不得是同一 (集,秒)。不同集、或同集但时间窗不重叠(不同场景)算不同画面,允许
- **每条解说稿最后一句必须是朗读出来的引导**(进 TTS 音轨,不只是字幕),格式=**2 个该故事线专属的悬念问题 + 引导**。问题要量身定做、勾"必须看下去才知道答案"(例:养老题材"谁会惩罚这两个不孝子";逆袭题材"赶走她的前夫会不会后悔";悬念题材"失踪的儿子到底还活不活着")
  - **抖音版引导 = 追更式**:除了「点击左下角看全集」,加一句**关注钩**「关注我看她怎么翻盘/复仇」——解决"几乎没关注":关注的本质是"预期你后面还有我爱看的",单条解说不给追更预期就永远是路人。
- **点赞钩(治"几乎没点赞")**:点赞=情绪共鸣/认同被触发。每条至少埋 1 处——① 情绪峰值(最惨/最反转那一下)配 BGM 推到顶 + 一句**价值判断金句**("一个救人的好人,活成了全村的笑话");② 或抛一句**评论区设问**("换你,能忍吗?")勾互动。情绪峰值金句尽量靠近结尾前(完播+点赞双吃)。
- **收藏钩(抖音 2026 收藏率第一权重,长解说必埋)**:开头一句「信息量大/反转多,建议先收藏别看丢了」+ 结尾一句「先收藏+关注追更」。给"值得存下来"的理由。
- **原声开场(抖音 2026,长短两版各一个、不共用)**:0–3 秒用原片最炸原声(尖叫/耳光/狠话)+ 同刻强表情画面,**非 TTS 旁白**。**字幕 = 原声那句台词(原声字幕),不写编辑化钩子句**(否则字幕对不上原声、出戏)。**长版和短版各挑一段不同的高燃原声+画面**(避免同账号判重 + 各贴自己角度)。技术做法见 Step 1「🔵 抖音 2026」第 2 条 + Step 4.6。
- **BGM 峰值推顶**:情绪峰值镜在 manifest 打 `"bgm_swell": true`,build 自动加音量关键帧(0.30→0.48→0.30)。
- **解说词字幕压在原片字幕位置上**(ty≈-0.50,正好盖住被模糊的原字幕条;源1440×2560与画布同9:16满铺,叠1.07放大后算得)
- 引流钩子「点击左下角  观看全集」字幕**底部居中**(ty≈-0.80)+ 全程显示
- **CTA 正下方显示《剧名》**(ty≈-0.91,字号与解说一致=8.5,全程;剧名自动取草稿名第一段)
- 顶部合规声明全程,**字号 6.5(不能太小,原 4.5 平台仍强制加"可能使用AI技术制作"标注)**,措辞「本视频由AI生成  仅供娱乐  无不良引导」,白色清晰可见
- **不加任何调色/氛围特效**(暗角/电影感/颗粒已移除)——画面差异化靠发布前的「成片去重 pass」(帧级打散),**不靠**加边框/镜像/贴纸遮挡(平台明确判这些=简单编辑,会被减推荐)
- N 条产物**时长必须各不相同**(靠每条句数/长短句差异自然拉开),且每条落在**所属平台区间**(抖音长解说 5–8min / 抖音短版对照 45–75s / 视频号 90–180s ≤3 分钟)

## 工具
| 脚本 | 作用 |
|---|---|
| scripts/desub_subtitles.py | **【去字幕首选】逐帧检测+只糊文字小框**(紧贴每行字幕,不满宽/不成大条/无字幕不糊;字幕位置逐场变也跟随)→ blurred/。OpenCV,分辨率无关 |
| scripts/tag_subcy.py | 逐镜检测原字幕中心(占高比例 sub_cy_frac)写回 manifest → build 让解说字幕**逐镜精确压在原字幕位** |
| scripts/blur_subs.py | 【旧版/备选】整条字幕区局部模糊(字幕位置固定的剧可用;位置乱跳/中部字幕用 desub) |
| scripts/tts_shots.py | 读一个 narration json → 逐句豆包TTS → tts_<stem>/ + <stem>_manifest.json |
| scripts/build_narration_mixcut.py | 【视频号】读 manifest → 纯解说快剪剪映草稿(第4参数 BGM,第5参数 GLOBAL_SPEED);**解说字幕逐句短句化**(按标点拆短句、逐句弹出+向上滑动入场);自动读 sub_cy_frac 逐镜对齐压原字幕位 |
| scripts/build_narration_mixcut_douyin.py | 【抖音】同上 + AI标注/剧名在标注下/CTA竖排贴左缘;第5参数 is_ai(1=AI剧加AI标注,0=真人剧右上角竖排"剧情演绎");**读 manifest shot 的 `bgm_swell` 标记自动加 BGM 音量关键帧(峰值推顶 0.30→0.48)** |
| scripts/insert_hook.py | **原声开场**:往 manifest 头插一个 `is_hook` shot(audio=原片抽的原声 mp3、非 TTS)。用法 `python insert_hook.py <manifest> <hook.mp3> <ep> <start_s> <dur_ms> <caption>`,幂等(已插过跳过) |
| scripts/validate_shots.py | 检测同一故事线内「连着相同画面」(源时间窗重叠/重复),build 前后都可跑 |
| scripts/render_narration_mp4.py | **【直出成品 MP4·不经剪映】**读同一 manifest,ffmpeg 直接合成 mp4:画面1.07放大+1.15加速+静音、解说1.4、BGM0.30、逐句字幕(向上滑入·落原字幕位)、竖排CTA(左中下)、声明(真人右上竖排/AI顶部横排)、剧名顶部、**镜间200ms叠化(xfade,每镜多渲0.2s使转场偏移=原硬切点→零漂移、解说不交叉)**、**bgm_swell镜BGM梯形推顶0.30→0.48**。用法 `python scripts\render_narration_mp4.py <manifest> <剧名> <输出mp4> <asr_work> [is_ai=0/1] [bgm]`。适合要 mp4 成片而非剪映草稿、或剪映版本太新(≥7)UI自动导出失效时 |
| scripts/desub_eps.py | 60fps/高分辨率剧 desub 太慢→精准逐帧检测**只处理指定集号**分片,多组并行调用提速(见 Step 3 提速) |

Python 用本机 `python`(3.12);需确保 `ffmpeg`/`ffprobe` 在系统 PATH 上(或设置环境变量 FFMPEG/FFPROBE 指向可执行文件)。

## 执行流程

### ▶ Step 1: 读全剧,规划 N 条故事线
> 📌 **选题先读 [references/benchmark-hook-templates.md](references/benchmark-hook-templates.md) 的「选题题材库」**——对标实证蒸馏:爽点内核=信息差打脸(主角是隐藏大佬被狗眼看人低→连环打脸),优先挑能立这个信息差的故事线。
- 读 `asr_work\_segments_compact.txt`(全剧紧凑台词,带集数+时间戳)
- 理清主线、人物、核心冲突
- **从全剧切出 N 条不同高光故事线**——不是连续上下集,是**同一部剧的 N 个不同切入角度**,每条自成一个有钩子有悬念的小故事(例:致死事件线 / 伪善揭穿线 / 施虐者A线 / 施虐者B线)
- **时长按平台分版(实测数据驱动)**:
  - **抖音(2026 机制)= 优先做长解说,短版只作对照**。⚠️ **别再套"越短完播越高"的 2025 旧逻辑**(已作废)。2026 抖音**完播率退居二线、"用户总停留时长"才是王道**(7min 视频看 4min 触发优质保护拿大流量;15s 视频哪怕 100% 完播看完就划也难进大池)→ **短剧解说在 2026 要做长不做短**。打法见下「🔵 抖音 2026 推流机制打法」。**默认标配出一长一短两版做 A/B**:**长解说 `sl_long.json`(5–8min,主推完整弧)** + **短版 `slN_dy.json`(45–75s,对照单角度)**,两版都发,用真实"平均停留时长 + 收藏数"定赢家、后面照赢家做。两版都走「前15秒重构」,且**各用一个不同的高燃原声画面开场**(不共用同一段,避免同账号判重 + 各取最贴自己角度的高能帧;如长版用打脸耳光、短版用换脸尖叫)。
  - **视频号 = 长版 90–120s 为甜点(上限 180s)**(≈ 18–28 句)。**机制依据**:视频号 L1 冷启动池晋级看的是**绝对停留时长(≥72秒)+ 互动率(≥8%)**,不是抖音那种完播率百分比。**所以视频号绝不能砍太短**——片长<90s,看进去的人平均停留摸不到 72 秒门槛,直接卡死底池(实测把视频号剧砍到 60-75s = 自杀)。视频号靠社交推荐(点赞/在看/转发=好友曝光),受众吃情绪铺陈,可保留铺垫和评述,但**留存必须做平**(见下「视频号留存+转化打法」)。
  - **默认一部剧只做归属的那个平台**(见开头「⛔ 平台分轨」)。若确需两平台都发,**当成两次独立执行**:同一故事线分别写两版稿(抖音砍铺垫+前置高潮 `slN_dy.json`;视频号保留铺陈 `slN.json`),各跑各的 build,**绝不一稿两投、绝不串参数**。
  - **命名约定(两版分开,别互相覆盖)**:
    - 视频号长版 = `slN.json` → `tts_slN/` + `slN_manifest.json` → 草稿名 `剧名_SLN_角度名`
    - 抖音短版 = `slN_dy.json` → `tts_slN_dy/` + `slN_dy_manifest.json` → 草稿名 `剧名_角度名_抖音短版`
    - **抖音长解说(2026 主推)= `sl_long.json`** → `tts_sl_long/` + `sl_long_manifest.json` → 草稿名 `剧名_完整解说_抖音长版`。
    - 两版/多版各自独立跑 Step 4 TTS / Step 4.5 tag_subcy / Step 5 build(`tag_subcy.py` 按 `sl*_manifest.json` 通配,都会被标注)。
    - **长解说 BGM**:单条 5–8min,伤感库单首最长才 240s 不够→用 `ffmpeg ... acrossfade=d=3` 把两首伤感拼成 ≥ 片长的一条(如 `_bgm_long.mp3`=伤感008+003 拼 457s)。BGM 须 ≥ 片长否则结尾静音。

#### 🔥 前15秒重构(抖音版强制 / 治"10-20s 断崖")
**实测教训**:数据反馈完播 ~10%、留存在 10-20s 直线下降 = **钩子兑现断层**——首句钩子把人留住了,但第 2-5 句开始"顺叙交代背景",信息增量断了人就划走。改法:
1. **最炸的反转/结局前置到 0-5s**——不是按剧情顺序从头讲,把全剧最有冲击力的那一下(被害/反转/真相)作为第一句 + 第一个画面。
2. **前 3 句全是钩子/冲突,零背景交代**。背景边推剧情边补,绝不在前 15s 铺垫。
3. **10-15s 处埋第二钩**:一句设问预告下一个反转("可真相是——""但你绝对想不到——"),让第一个悬念快讲完时立刻看到第二个。
4. **前 20s 每句画面都是强冲突动作**,不给"两人站着对话/脸大特写/空镜"。

#### 🔵 抖音 2026 推流机制打法(2026-06-17 联网查证纠偏 / 不同于 2025)
**真机制(查证,和 2025 完全不同)**:① 考核 24h→**7 天长效**(7 天内任意时段数据回暖就持续加推,不用赌发布瞬间);② **完播率退居二线,"用户总停留时长"才是王道**;③ 互动权重排序 **收藏 > 复访 > 评论 > 转发 > 点赞**(收藏第一);④ 前 3 秒仍"开场即高潮"+ **文字钩转视听钩**;⑤ **2026.1 起 AI 生成视频必须发布时勾平台级"内容由AI生成"标签否则降权**(烧字幕替代不了,提醒用户在抖音发布界面勾)。据此:
1. **做长拉总停留(主推)**:把整部剧拆成 **1–2 条 5–8min 完整长解说**(完整复仇/逆袭弧 + 密集反转,每 5–8 秒一个信息增量,中段不留尿点),拉总停留时长 + 够长触发优质保护。长解说脚本 = `sl_long.json`(~45–55 句,5.5–5.8 字/秒换算 ~270–320s),命名/产物见下。
2. **原声开场(视听双钩,长短版都加)**:0–3 秒用**原片最炸的原声**(尖叫/耳光/惨叫/狠话)+ 同刻强表情画面,**不是 TTS 旁白开场**。⚠️ **开场字幕必须 = 原声实际说的那句台词(原声字幕),不要写编辑化钩子句**——否则字幕和原声对不上、出戏(踩过坑);这些原声台词本身就是钩子,原样上字幕即可。做法:`ffmpeg` 抽原片那 2–4 秒原声→ `loudnorm`(末尾/中间死静音要剪掉,用 `silencedetect` 验)→ `scripts\insert_hook.py` 往 manifest 头插一个 `is_hook` shot(`audio_path`=原声 mp3、非 TTS;`pic`=同刻画面;`text`=**原声那句台词**)。**长版和短版各挑一段不同的高燃原声+画面开场,不共用同一段**(避免同账号判重 + 各取最贴自己角度的高能帧;例:长版打脸耳光、短版换脸尖叫)。挑帧先抽几帧肉眼确认"音强+画面也强",别只看音频。
3. **收藏钩(2026 收藏率第一权重,必埋)**:长解说**开头**一句「信息量大/反转多,建议先收藏别看丢了」+ **结尾**一句「先收藏+关注追更」。给观众"值得存下来"的理由(完整故事线/反转合集)。
4. **BGM 峰值推顶(情绪驱动收藏/点赞)**:最惨/最反转/最爽那几下,BGM 从 0.30 推到 ~0.48 再回落。做法:manifest 给峰值镜打 `"bgm_swell": true`,build 自动加剪映原生音量关键帧(默认无标记=全程 0.30 不变)。
5. **合规**:顶部烧「本视频由AI生成…」声明 **+ 提醒用户发布时勾平台级 AI 标签**(两者都要,字幕替代不了系统标签)。

#### 🟢 视频号留存+转化打法(推流机制驱动 / 2026-06-17 实测纠偏)
视频号卡 300 = L1 冷启动池没晋级,本质是「**双锁**」:① 平均停留<72秒(留存差)② 互动率<8%(没赞没转)。两把锁都要破:
1. **够长(90–120s)+ 留存做平**:片长要给"看进去的人"留出突破 72 秒停留的空间;同时前3秒最炸(3秒播放率>50%才进推荐页)、前18秒钩子套钩子、**全程无尿点**(每 10–15 秒一个小钩/反转/设问,不留平铺段)。完播冲过 45% 触发二次推流。
2. **互动靠内容自然引发,绝不喊话**:每条埋 ≥3 处**情绪峰值金句**(如"一个救人的好人,活成了全村的笑话"),靠情绪共鸣自然带来点赞/在看/自发转发。⚠️ **禁止喊话求赞/求转/求关注/"扣1"/"评论告诉我"**——这是平台明令违规;苦情题材(老实人被欺负)上叠加"要赞要关注"会被判**煽动对立**双重违规。
3. **结尾悬念断点 + 合规引导(转化核心)**:解说讲到最爽的反转/报应/真相**前一秒戛然而止,绝不剧透结局**,末句=量身定做的悬念问题 + **「点左下角,看完整全集」**(指向挂载的**短剧小程序组件**,官方 CPS 合规路径,需有效粉丝>1000)。靠"好奇心必须被满足"逼出点击,不靠转发喊话。
4. **合规红线(违反=限流/封号)**:不诱导赞/转/关注/评论、不奖励诱导(集赞/分享抽奖)、不导流站外私域、不绝对化用语、不"要互动+煽动对立"。

### ▶ Step 2: 写解说稿(每条一个 narration json)
写到 `asr_work\narration\sl1.json … slN.json`,格式:
```json
{
  "storyline": "五十块钱的命",
  "voice_type": "zh_male_M392_conversation_wvae_bigtts",
  "speed_ratio": 1.2,
  "shots": [
    {"text": "首句必须是强钩子……", "pic": {"episode": 1, "start_s": 0.2}},
    {"text": "第二句……", "pic": {"episode": 2, "start_s": 4.8}}
  ]
}
```
- **语气**:第三人称网感苦情解说腔 = 口语化 + 情绪共鸣 + 愤慨设问 + 破折号留扣;不书面、不AI腔、不堆语气词
- **原创评述(防判重必做)**:解说不能只复述剧情(平台会判"高度相似/简单编辑"减推荐)。每条至少 2–3 句要带**解说者的观点/态度/价值判断/反问**——评一句人物("这种婆婆嘴上狠、心里疼")、点一句因果("作到这份上,不塌房才怪")、抛一句共鸣设问("换你能忍?")。这是平台"融入个人观点/分析"的硬要求,也是和他人搬运版拉开差异的核心
- **画面锚定**:每句 `pic` 必须落到剧中**真正在演那件事**的台词时间点(从 `_segments_compact.txt` 取真实集数+秒)
- 末句=**2 个故事线专属悬念问题 + 点击左下角，观看全集**(整句进 TTS;问题量身定做,见上方产物约定)

#### ⏱ 时长一次到位(首轮就写够,别靠事后反复重 TTS)
**实测教训**:解说句写太短,首轮 TTS 常只有 65–85s,够不到 90s 下限,只能来回加料重跑 TTS(单部剧浪费 8–10 分钟)。首轮就按下面的量写,基本一次进区间。

speed_ratio=1.2 下,豆包 TTS 约 **5.5–5.8 字/秒**(含标点;实测 sl1 17 句 ≈100.9s)。换算:
| 单句字数(含标点) | 约时长 |
|---|---|
| 28–32 字 | ~5.3s |
| 33–38 字 | ~6.2s |
| 40+ 字 | ~7.2s+ |

**写稿目标**:正文句按 **30–38 字 / ~6s** 写;首句钩子可到 ~7–8s;末句 CTA 较短(~5s)。
**句数 ≈ 目标时长 ÷ 6**。**抖音短版 45–75s → 8–12 句**;**视频号长版 90–180s → 15–28 句**(想稳到 ~120s 写 ~20 句、~150s 写 ~25 句)。
**N 条首轮就把时长定不同**(避免事后为"各异"返工):例如目标 **108 / 102 / 96 / 92s**,对应不同句数/句长,天然拉开 ≥4s。

⚠️ **不许靠废话凑时长**(伤质量):字数要来自**具体细节**——场景、数字、人物动作、情绪、破折号留扣;不是加语气词、不是把一句话注水。写完心算一遍总字数 ÷ 5.5 ≈ 秒数,落对应平台区间(抖音 45–75 / 视频号 90–180)再去 TTS。

#### ✅ 解说文案钩子验证规则(写完首句必过,否则重写)
> 📌 **写 shot[0] 前先套 [references/benchmark-hook-templates.md](references/benchmark-hook-templates.md) 的「开头钩子句式模板」**(红尘短剧实证公式:`[主角身份/处境]+[意外发现/反常细节]+[强冲突动作]`,零铺垫);中段照「密集信息差打脸」节奏、结尾照「断在反转峰值+接原片惊呼」收口。下面是验证规则:

首句(shot[0])必须命中下列至少一条强钩子型,且 **15 秒内能说完**:
1. **悬念设问**——抛一个让人必须看下去才能解答的问题("你敢信吗?一条人命只值五十块?")
2. **反差/信息差**——把违反常识的事实摆前面("活着五十块嫌贵,死了却办最体面的葬礼")
3. **震惊事实前置**——把全条最炸的冲突点直接甩出来("两个儿子为了亲妈养30天还是31天,当面打了起来")
4. **身份+绝境**——主角是谁 + 被逼到什么份上("六十多岁的亲妈,被亲儿子安排住进又潮又黑的地下室")

**禁止的弱开头**(命中即重写):
- 平铺背景交代("故事要从十二年前说起……")当**首句**
- 主语模糊、信息密度低、看完第一句不知道这条要讲啥
- 把结局/和解/温情当开头(钩子要冲突峰值,不是落点)

自检:把首句单独念出来,一个没看过剧的人会不会想点开看下去?不会 → 重写。

### ▶ Step 3: 去硬字幕(精准逐帧,首选)
```powershell
# 确保 ffmpeg 在 PATH 上（如未加入：$env:PATH="<你的ffmpeg目录>;"+$env:PATH）
python scripts\desub_subtitles.py "<asr_work>" [y0=0.45] [y1=0.95] [white=225] [dark=70]
```
- **逐帧检测「白字黑边」文字框 → 只糊那一小块**(紧贴每行/不满宽/不成大条/无字幕的帧不糊),字幕位置逐场跳也能跟随。
- 自动 union narration 引用集,读 merged_data 的 video_path(文件名任意,不依赖"第N集"命名),输出 blurred/<原名>.mp4,已存在跳过。
- **🟢逐集自动锁定字幕带(2026-06-25 重写,治「码乱飞」)**:开跑前先采样全片,取「居中检测框」y 中心主峰 = 真实字幕行,之后检测 ROI **只看这条带 ± 余量,根本不扫人物区**;再叠**水平居中约束 + 单框对称收敛 + 时间去抖(连续≥2帧才开+几何EMA+短暂保持)**。脚本每集打印 `lock cy=1300(67.7%) half=52`——看这行就知道锁得对不对,**换剧不必再手动探测/量像素带**。y0/y1 只是「搜索范围」,默认 0.45–0.95 通吃中下部字幕;只有锁错带(打印的 % 明显偏离真字幕)才调。
- 漏检才需调参:低对比可降 white/升 dark;`未锁定字幕带, 回退整带` 提示=该集没采到稳定带,多为纯无字幕片段或字幕在搜索带外(调 y0/y1)。
- **核验**:对每个镜头的整段时长逐秒抽 blurred 帧重跑检测器/肉眼看,确认①字幕条被糊②人物背景**零误糊零飞框**——别只看几帧。
- 旧版 `blur_subs.py`(整条 blur)仅在字幕位置固定且不在意大条遮挡时用。
- **⚡提速(60fps/高分辨率剧必看)**:`desub_subtitles.py` 单线程在 60fps 片上慢到 ~10-15min/集。**正解=精准逐帧不变 + 并行分片**(把引用集分 N 组,`desub_eps.py <asr_work> <y0> <y1> <ep,ep,...> [white] [dark]` 各跑一组,复用同一套核心含自动锁带,6 组并行 ~29min/22集@60fps)。**绝不能为提速改成 ffmpeg 整宽带状模糊**——会糊一大条贯穿画面,违反"只精准糊字幕"硬底线(用户当场否决过)。自动锁带已替代旧的 `_probe_detect.py` 单帧画框探测。

### ▶ Step 4.6: 原声开场 + 峰值标记(抖音 2026,tag_subcy 之后 / build 之前)
1. **抽原声**:`ffmpeg -ss <t0> -to <t1> -i 原片.mp4 -vn -af loudnorm hook.mp3`(2–4s,最炸那句原声)。**必查死静音**:`ffmpeg -i hook.mp3 -af silencedetect=n=-30dB:d=0.2 -f null NUL`——中间有 ≥0.3s 静音就两段 `atrim` 拼掉(别留死气)。先抽几帧肉眼确认画面也强。
2. **插开场**:`python scripts\insert_hook.py "<manifest>" "<hook.mp3>" <ep> <start_s> <dur_ms> "<原声那句台词>" <sub_cy_frac>`(往 manifest 头插 is_hook shot;**caption 必须=原声实际台词**;`sub_cy_frac` 传该剧实测字幕位,如玉米地 0.586/蛊镯 0.683)。**长版 manifest 和短版 manifest 各插一段不同的高燃原声开场**(不共用,防判重)。⚠️ hook 画面集若未在该版引用过,要先 `desub_eps.py` 给它去字幕(否则露原字幕)。
3. **标峰值**:手改 manifest,给最惨/最反转/最爽那几镜加 `"bgm_swell": true`(2–3 处)。
4. 插完/改完重跑 `validate_shots.py` 确认 0 违规。

### ▶ Step 6: 出标题 + 标签(每条一组,写 `narration\titles.md`)
build 完成后,给**每条故事线**配一条**带钩子的发布标题 + 一组标签**。标题都要**冲突峰值前置、留悬念不剧透结局**,但**两平台规则不同**:

**视频号**——受众偏中老年/情感向,靠**情感共鸣 + 转发到群和朋友圈**扩散,语气口语苦情:
- **硬规:≤16 字(含标点、数字也算字数)**。超了就砍——优先砍背景词,保住「冲突点 + 数字 + 悬念」。
- 16 字塞不下完整因果时,只留**最炸的那个冲突点**(如「一条命才14万」「为多养一天打架」),铺垫丢进正文。

**抖音**——不靠转发靠**完播 + 推荐池**,标题**无 16 字硬限可长**:
- 但**前 15 字仍要独立成钩**(常做封面大字),突出冲突反转 + 数字悬念。

(标签规则见下方「标签做法」,两平台标签策略不同)

**标题做法:钩子公式 → 优化铁律**
1. 按故事线属性选钩子型(和解说首句同源,但标题更短更狠):
   - 反转/逆袭 → 「被X逼到绝境,她转头Y」(犯错反而好结果 / 从X到Y)
   - 信息差/震惊事实 → 把违反常识的数字或事实摆最前(「一条人命才赔14万,却…」)
   - 打脸/争议 → 「被诬陷X,结果一招让对方下不来台」
   - 因果反讽 → 「为了X赶走我,他们Y,最后Z」/ 纯悬念设问「那笔X最后进了谁口袋?」
2. **5 条优化铁律(逐条过)**:
   - **留悬念,不说答案**——只抛冲突,不剧透结局(用「后来才知道」「结果」收口,别把反转说完)
   - **话题扩大**——用普世词(逆袭/打脸/被赶走/报应)替行业黑话
   - **击中真实痛点**——被抛弃、被欺负、苦尽甘来、恶人自食其果
   - **张力检查 ≥2 项**——反差 / 数字 / 悬念 / 冲突 / 时间承诺 / 结果承诺,至少命中 2
   - **首屏可读 + 易转发**——视频号标题前 15 字要能独立成钩(常当封面大字/口播首句),且情绪点要让中老年观众想转发到家庭群

**标签做法**:`通用基础标签(全条共用) + 每条专属 2–3 个`,共 6–8 个。
- 通用:`#短剧解说 #短剧推荐 #情感短剧 #小人物逆袭 #爽剧`
- 专属:取该条题材关键词(如 `#拆迁 #嫁傻子 #当众打脸 #因果报应`)。
- **平台差异**:视频号靠 `#话题` 进垂类聚合页,标签精准即可;抖音标签更吃推荐分发,可多带题材词凑 5–8 个。
- **⚡抖音标签蹭实时热点(必查证、别用陈旧通用词凑数)**:发布前**联网查当下(当月)最火的题材词/爆款赛道**,挑**本剧名副其实**的热门词放进标签(抢这些词的搜索+推荐流量)。例(2026-06 查证):AI女频短剧涨粉快3-5倍→ `#AI短剧`;嫡女/宫斗爆款带火 `#嫡女`;黑莲花复仇爆款带火 `#黑莲花复仇`;本剧奇设差异化抢搜索 `#换魂`。⚠️ **只蹭题材词,不蹭别人剧名**(给自己解说挂别的剧名=误导+易判违规)。两条同剧标签错开 1–2 个降同质化。

`titles.md` 格式(每条):
```
## SL1_角度名
标题:前夫嫌我生不出娃把我赶走，我转头嫁了全村最穷的傻子
钩子型:犯错反而好结果 + 反转 | 张力:反差/冲突/悬念(3)
标签:#短剧解说 #短剧推荐 #小人物逆袭 #爽剧 #净身出户 #嫁傻子 #逆袭打脸
```
最后给一个 **Top 推荐排序**(哪条点击潜力最高,一句话理由),供用户优先发。

### ▶ Step 7: 发布前去重(防"高度相似"判重)
平台会判「与已发表视频高度相似」减推荐——**直接裁剪/镜像/加边框/贴纸马赛克遮挡 都算"简单编辑"会被判**。本 skill 的成品虽有原创解说+去字幕,但画面仍来自原片,跨号或同剧多条发布前**必须做帧级去重**:
1. 出成片 mp4:**①剪映里手动导出**草稿;或 **②`scripts\render_narration_mp4.py` 直出 mp4 不经剪映**(剪映版本太新自动导出失效、或只要成片不要草稿时优先用②,效果已对齐草稿:叠化+BGM推顶+逐句字幕+全套叠加)。
2. 对成片跑 **`video-dedupe-pass`**(另一个 skill):打散帧 pHash / 音频 MFCC / CLIP 帧向量 / 区域 pHash / 元数据指纹,可选叠加移动水印做账号标识。
3. **降同质化的两道闸**:① 原创解说评述(Step 2,内容层)② 成片去重 pass(像素/音频层)——两道都要,只靠一道仍可能被判。
4. **禁用**:加黑边/边框、镜像翻转、贴纸或马赛克盖水印——这些平台明确判"简单编辑",越做越糟。
> 触发词记忆:用户说"被判重/减少推荐/高度相似/防搬运/多号分发",就走 `video-dedupe-pass` 处理成片。

### ▶ Step 8: 发布前热点标签刷新(★每次发布前必做,用户已确认)
**热点是会变的(月级),发布前必须重查当下最火题材词、刷新标签**——不能直接用上次/旧的标签。
1. **联网现查当月热点**:搜「抖音 短剧 热门排行榜 <当年当月> 爆款」+「抖音 短剧 话题标签 热度 <当月> 女频/AI/题材关键词」,看当下爆款赛道/题材词(如某月 AI女频、嫡女、黑莲花复仇、换魂)。
2. **挑本剧名副其实的热门词**塞进标签(抢搜索+推荐流量)。⚠️ **只蹭题材词,不蹭别人剧名**(挂别的剧名=误导+易判违规)。
3. 刷新 `titles.md` 的标签段,两条同剧标签错开 1–2 个降同质化。
> 触发词:用户说"刷新标签/查热点配标签/发布前看热点/标签蹭热点",就跑这步(联网查 → 改 titles.md)。**别凭记忆给标签,当月现查。**

## 质量验证(Gate,build 后逐条过)
build 完成后,**每条草稿**必须核以下项,任何一条不过就修对应稿/重 build:

**① 时长(按平台)**
- **抖音长解说 5–8min(2026 主推)** / 抖音短版对照 45–75s / **视频号长版 90–180s(≤3 分钟)**。脚本结尾打印 `total: Xs`,不落在**对应平台**区间就增删解说句。别拿短版区间去卡长解说。

**② 轨道完整**
- 草稿应有 7 轨:画面 / 解说 / 字幕 / 引导 / 剧名 / BGM / 声明。**不应**出现任何特效轨(暗角/电影感/颗粒)。
- 顶部声明**字号 6.5、白色、全程清晰可见**(别再用 4.5 那种小到平台无视的)。

**③ 画面锚定准**
- 抽查 3–5 句:`pic.episode + start_s` 对应的画面,是否真在演这句解说说的事?锚错就改 narration json 的 pic 再重 build。

**④ 画面不空/不越界**
- 引用集都有 blurred 版(无则用原片,会带双层字幕)。
- start_s 不能超过该集时长(否则画面为黑/定格)。

**⑤ 钩子**
- 每条首句过上面的「钩子验证规则」。

**⑥ 字幕不切半句**
- 解说是整句 TTS,字幕=整句,天然不切;但人工扫一遍有没有句子过长导致一屏放不下。

**⑦ 音量**
- 解说 1.4、BGM 0.30。在剪映里听一遍:BGM 听得清但不压解说,解说峰值不破音(飙黄不飙红)。

**⑧ BGM 各异**
- N 条用了 N 首不同 BGM,且每首 ≥ 对应片长。

**⑨ 无连续相同画面**
- `validate_shots.py` 输出「合计违规: 0」。

**⑩ 时长各异**
- N 条时长两两不同(差值 ≥ 数秒,不是 0.1s 级),且均落在**各自平台区间**(抖音 45–75s / 视频号 90–180s)。

**⑪ 标题+标签齐**
- `narration\titles.md` 内每条都有:带钩子标题(过 5 条铁律,张力 ≥2)+ 6–8 个标签(通用 + 专属)+ Top 推荐排序。标题不剧透结局。
- **每条标题(含备选)逐字数过:≤16 字(含标点、数字)**,超一个字都要砍。

**⑫ 原创评述(防判重·内容层)**
- 每条解说不只复述剧情:至少 2–3 句带观点/态度/因果点评/共鸣反问(见 Step 2)。纯复述=易被判"高度相似"。

**⑬ 发布前去重(防判重·像素层)**
- 跨号 / 同剧多条发布前,成片必须跑过 `video-dedupe-pass`(见 Step 7)。**禁**加边框/镜像/贴纸遮挡。
- 顶部声明字号 ≥6.5 且清晰(见 ②)。

**⑭ 原声开场(抖音 2026,长短各一)**
- 长版、短版**各有自己的原声 hook**:解说轨**第 1 段 = 原声 hook mp3(非 TTS)**、开场画面=同刻 blurred、hook 原声**无中间死静音**(silencedetect 验过)、**开场字幕 = 原声那句台词(原声字幕,跟音频一致)**。**两版 hook 必须是不同的原声+画面**(防同账号判重)。

**⑮ 收藏钩(抖音长解说)**
- 开头 + 结尾各 ≥1 处收藏引导文案(2026 收藏率第一权重)。

**⑯ BGM 峰值推顶(抖音 2026)**
- 标了 `bgm_swell` 的剧:BGM 段有音量关键帧(draft 里 `common_keyframes` 含 `KFTypeVolume`)。

**⑰ AI 标签合规(2026.1 新规)**
- AI 剧:除画面烧「本视频由AI生成」声明外,**提醒用户发布时在抖音界面勾平台级"内容由AI生成"标签**(系统标签,字幕替代不了,否则降权)。
